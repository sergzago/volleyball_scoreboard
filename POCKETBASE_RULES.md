# Правила доступа PocketBase

## Обзор

Доступ к данным осуществляется через сервисный клиент `app_users` (технический
пользователь `app@volleyball.local`).  Этот клиент аутентифицируется в коллекции
`app_users` и используется для всех операций изменения данных — аналогично
созданию/удалению пользователей.

**Все коллекции используют одинаковую схему правил:**

| Правило     | Значение | Описание |
|-------------|----------|----------|
| `listRule`  | `""`     | Любой авторизованный пользователь может читать список |
| `viewRule`  | `""`     | Любой авторизованный пользователь может читать запись |
| `createRule`| `""`     | Любой авторизованный пользователь может создавать запись |
| `updateRule`| `""`     | Любой авторизованный пользователь может обновлять запись |
| `deleteRule`| `""`     | Любой авторизованный пользователь может удалять запись |

Контроль ролей (`admin`/`user`) осуществляется на уровне приложения
(`admin.html`, `mobile.js`) — функции `isCurrentUserAdmin()` и `isAdmin()`
проверяют роль текущего пользователя **до** вызова `DB.*`.

## Коллекции

### `app_users`
| Правило | Значение |
|---------|----------|
| Manage Rule | `@request.auth.id = id` |
| Auth Rule | *(пусто)* |
| createRule | `null` (только суперпользователь) |
| deleteRule | `null` (только суперпользователь) |

**Описание:**
- Пользователи могут редактировать только свой профиль (`@request.auth.id = id`)
- Авторизация разрешена для всех (пустое Auth Rule)
- Создание/удаление записей — только через админ-панель PocketBase
- Эта коллекция **не имеет поля `role`** — это техническая коллекция для сервисного клиента
- Используется функцией `getPocketBaseServiceClient()` для создания/удаления пользователей и турниров

### `scoreusers`
| Правило | Значение |
|---------|----------|
| listRule  | `""` |
| viewRule  | `""` |
| createRule| `""` |
| updateRule| `""` |
| deleteRule| `""` |

**Описание:** Все CRUD-операции доступны любому авторизованному пользователю
из `app_users`.  Создание/удаление пользователей выполняется через
`getPocketBaseServiceClient()` — аналогично созданию турниров.

**Поля:**
- `username` (text, required)
- `email` (email, required)
- `password` (password, required)
- `name` (text)
- `role` (select) — `admin` или `user`
- `emailVisibility` (bool)

**Создание и удаление турниров** выполняется через `getPocketBaseServiceClient()`
(аутентификация как `app@volleyball.local`), **аналогично** созданию и удалению
пользователей в коллекции `scoreusers`.

**Важно:** `deleteRule` **НЕ** использует `role = "admin"`, потому что коллекция
`app_users` не имеет поля `role`.  Проверка прав администратора выполняется в
коде приложения (`isCurrentUserAdmin()` в `mobile.js`, проверка роли в
`admin.html`).

## Как настроить

1. Откройте **PocketBase Admin UI** (`http://zago.my.to:8091/_/` или `https://zago.my.to/pb/_/`)
2. Перейдите в **Settings → Collections**
3. Для каждой коллекции установите правила из таблицы выше
4. **Либо** импортируйте коллекции из JSON-файлов (`pb_collection_*.json`) через
   **Settings → Import collections** — правила будут применены автоматически

> **Если коллекция уже существует** и правила не применяются: удалите коллекцию
> и импортируйте заново из JSON-файла.

## Технические пользователи

Файл `credentials.js`:

```js
pocketbase: {
  url: 'https://zago.my.to/pb/',
  user_email: 'app@volleyball.local',   // Технический пользователь
  user_password: '...'
}
```

Этот пользователь используется для всех операций с данными (создание матчей,
управление пользователями, создание/удаление турниров, логирование).
